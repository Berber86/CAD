# 4.81.11 — Модели Hydra: только Vision + настраиваемые рассуждения, переключатель уровня в программе

Список моделей Hydra пересмотрен по публичному каталогу провайдера
(`GET https://api.hydraai.ru/v1/models`, проверка 2026-11-23). Оставлены и
добавлены только модели, у которых вход одновременно текст+картинка
(`input_modalities`) и есть настраиваемый уровень рассуждений
(`reasoning_effort` с выбором значений):

`grok-4.7` (новая модель по умолчанию — рабочая модель Николая вместо
текстовой `glm-5.2`), `gemini-3.1-pro`, `gemini-3.8-flash`, `gemini-3-flash`,
`gemini-3.1-flash-lite`, `gpt-5.2`, `gpt-5.1`, `gpt-5.4-mini`, `gpt-5.4-nano`,
`gpt-5.6-luna`, `claude-sonnet-5`, `minimax-m3.1-flash`,
`pro/deepseek-v4.1-flash-1017`, `pro/glm-5.3-flash`.

Удалены текстовые модели без визуального входа: `glm-5.2`, `hydra-gemini-pro`,
`hydra-gemini-3-pro`, `hydra-gemini`.

Что изменено:

- `llm_parser.py`: новый список в `PROVIDERS_CATALOG.hydra`, таблица
  `HYDRA_MODEL_REASONING` (дефолт провайдера и допустимые уровни каждой
  модели из каталога), `reasoning_spec()` / `resolve_reasoning_effort()`.
  Выбор пользователя хранится в `api.providers.hydra.reasoning_by_model`.
- Миграция в `load_config`: пользовательский `config.json` обновлением не
  перезаписывается (`app_updater`), поэтому удалённые модели вычищаются из
  списков и выборов на месте, Vision-модели добавляются, выбранная удалённая
  модель заменяется на `grok-4.7`. Ручные имена моделей не трогаются.
- Уровень рассуждений реально уходит в запросы верхним уровнем
  (`reasoning_effort` через `extra_body`) во всех путях: одиночный разбор и
  консенсус (`_extract_with_llm` — все 4 формата каскада), ИИ-советник
  (`ask_llm_json`), Vision-автоповорот, транспорт нескольких описаний.
  Если провайдер отклоняет параметр, запрос повторяется без него (модель
  отвечает на своём дефолте) — по образцу автоснятия `temperature`.
  Моделям без описанных уровней параметр не отправляется.
- `main.py`: под каждой моделью в настройках (проходы 1–3) — переключатель
  её уровня рассуждений из допустимых значений модели; при выборе ровно
  1 прохода тот же переключатель вынесен в главное окно (карточка «Режим
  разбора», там же уровень виден подписью «рассужд. …»). Выбор сохраняется
  в конфиг и подхватывается при следующем запуске.
- Модель по умолчанию сменена с `glm-5.2` на `grok-4.7` (`DEFAULT_CONFIG`,
  поставляемый `config.json`, все запасные подстановки).

Проверки: `tests/test_hydra_reasoning.py` (каталог, дефолты/выбор/миграция,
проброс `reasoning_effort` в фейкового провайдера, повтор без параметра при отказе,
сквозной однопроходный консенсус, транспорт нескольких описаний) и GUI-тест
переключателей в `tests/test_gui_smoke.py`. Живые платные запросы не запускались:
фактическая поддержка каждого уровня каждой моделью проверяется первым
реальным запуском (при отказе параметр снимется автоматически).
