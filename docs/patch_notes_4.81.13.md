# 4.81.13 — Порядок списка Hydra: Грок первым, дальше по цене; предупреждение о дорогих моделях

По просьбе пользователя:

- Список моделей Hydra переупорядочен: `grok-4.7` — первым (и остаётся
  моделью по умолчанию), остальные идут по возрастанию цены миллиона
  выходных токенов, самые дорогие — в самый низ:
  gpt-6-luna (20 ₽) → minimax-m3.1-flash (24) → pro/glm-5.3-flash (36) →
  gpt-5.6-luna и pro/deepseek-v4.1-flash-1017 (48) → gpt-5.4-nano (50) →
  gemini-3.1-flash-lite (60) → gpt-5-mini (80) → gemini-3.5-flash-lite (100) →
  gemini-3-flash (120) → gemini-3.8-flash (150) → gpt-5.4-mini (180) →
  gpt-6.1-terra (200) → модели по 400 (gpt-5.1, gpt-6-sol, gpt-6.1-sol,
  gpt-6.2-sol) → claude-sonnet-5/5.5 (470) → gemini-3.1-pro и gpt-5.6-terra
  (480) → gpt-5.2 (520) → gpt-5.3-codex (560) → gpt-5.4 (600) → gpt-5.5 и
  gpt-5.6-sol (1200) → gpt-6.2-astra (1600) → gpt-6-astra (2000).
  Порядок задаётся в `PROVIDERS_CATALOG` и через миграцию `load_config`
  применяется и к уже установленным копиям (ручные модели пользователя
  по-прежнему сохраняются после каталожных).
- Предупреждение «это будет дорого»: при выборе в любом используемом проходе
  модели с ценой выхода выше 1000 ₽ за миллион токенов (порог
  `EXPENSIVE_OUT_RUB_PER_M` в `llm_parser.py`; сейчас это gpt-5.5,
  gpt-5.6-sol, gpt-6.2-astra, gpt-6-astra) строка статуса показывает
  предупреждение «⚠ Это будет дорого: модель … — больше 1000 ₽ за миллион
  выходных токенов». Срабатывает при выборе модели и при смене провайдера
  основного прохода. Цена берётся из `model_output_price_rub()` (данные
  каталога Hydra от 2026-11-23).

Проверки: порядок и порог — в `tests/test_hydra_reasoning.py`, предупреждение
в интерфейсе — `test_expensive_model_selection_warns` в
`tests/test_gui_smoke.py`. Живые запросы не запускались.
