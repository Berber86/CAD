# Patch notes 5.16 (2026-11-24)

## Дискета → OK без промежуточного снимка

Предложение пользователя по живому скачиванию ACRIS: после дискеты не делать
лишний снимок и OCR ради кнопки OK, а нажимать её через секунду по уже
известным координатам.

Сделано именно так, с калибровкой на первом проходе:

- первый документ в запуске по-прежнему находит OK по OCR и запоминает
  смещение центра OK относительно точки дискеты для этого браузера и размера
  окна;
- следующие документы: дискета → ровно 1 секунда → клик по вычисленной точке
  OK, без снимка и без OCR между кликами;
- если после быстрого OK PDF не пошёл за 8 секунд, программа один раз смотрит
  экран: диалог ещё открыт — нажимает настоящее OK и перекалибровывает точку.
  Это спасение на случай, если вёрстка читалки сдвинулась, а не проверка на
  успешном пути.

## Что ещё ускорено рядом

- Ожидание PDF в «Загрузках» опрашивает папку раз в 0.25 с вместо 1 с:
  файловая проверка дешёвая, снимок для неё не нужен.
- `find_new_pdf` больше не открывает каждый PDF в папке на каждом опросе:
  кандидаты сортируются по времени, и чтение прекращается на первом файле с
  настоящей сигнатурой `%PDF-`.
- Отсечка «какие загрузки считать новыми» в читалке ставится после нажатия
  OK, а не до открытия документа: оставшийся в «Загрузках» PDF предыдущего
  документа не примется за результат текущего клика.
- Браузерный резерв ACRIS (форма BBL) больше не делает отдельный снимок+OCR
  на каждое поле: один снимок формы обслуживает Block, Lot и кнопку Search —
  от ввода цифр подписи и кнопка не переезжают.

Сознательно не тронута двойная проверка живой читалки перед дискетой: она
ловит отложенный HTTP 405, из-за которого читалка уже подводила на живых
прогонах. Там цена ошибки выше сэкономленной секунды.

## Проверка

Полный набор: 2103 теста, 14 skipped, 2 xfailed — зелёный. Новые тесты:
второй документ нажимает OK ровно через 1 с и без единого снимка после
дискеты; промах быстрой точки спасается одним снимком и перекалибровкой.
