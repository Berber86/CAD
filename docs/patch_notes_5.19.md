# 5.19 — подсказка портала выбирается кликом мыши, а не Down+Enter

Дата: 2026-11-24.

## Живой сбой

Задание 3868 (59-11 Fresh Pond Road, Queens) остановилось на поиске адреса:
подсказка «59-11 FRESH POND RD, QUEENS, NY, 11378, USA» была найдена и
«выбрана», но карточка не появилась. На снимке сбоя в поле — подпись
подсказки целиком, красная плашка «Address not found within the NYC limits»
и «No results»: Down+Enter превратились в **текстовый поиск по подписи
подсказки**, который портал отклонил. Вводился при этом верный адрес из
названия папки; подпись в поле подставил сам портал при «выборе» клавишами.

## Что изменилось

Выбор первой подсказки теперь делается как человек — кликом мыши:

1. клик по центру первой строки подсказки (строка по-прежнему находится
   только по тексту, без геометрии; координаты — лишь точка клика);
2. если карточки нет, а на форме видна кнопка **Search** — клик по ней
   (портал мог ждать явный поиск после выбора);
3. если портал отклонил поиск по тексту («…not found…» / «No results») —
   адрес вводится заново и подсказка выбирается кликом ещё раз;
4. последним шагом — прежние Down+Enter.

Каждое действие проверяется ожиданием карточки. Быстрый режим не тронут
(там по-прежнему паузы и клавиши). Распознавание подсказки, отказ от
строгой сверки текста и все задержки ожидания — без изменений.

## Проверка

- Регрессионный тест случая 3868: отказ текстового поиска → повторный ввод
  → клик по подсказке → карточка Queens 2754/21.
- Тест кнопки Search после клика по подсказке.
- Обновлены сквозные тесты драйвера портала (клики вместо клавиш в выборе
  подсказки; меню Select по-прежнему управляется клавишами).
- Полный pytest: **2115 passed, 14 skipped, 2 xfailed**.

Живая проверка — первым заданием с поиском адреса на NYC Portal: в журнале
должно быть «выбираю первую подсказку кликом мыши».
