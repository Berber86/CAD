# 5.25 — выбор нескольких папок работ одним диалогом (Ctrl/Shift)

Дата: 2026-11-25.

## Живая просьба (пользователь, страница «Данные»)

Папки в очередь добавлялись по одной: tkinter `askdirectory` мультивыбора не
умеет, а проводник каждый раз открывался внутри предыдущей папки — приходилось
подниматься на уровень вверх ради каждой следующей папки. Пользователь просил
выбирать сразу несколько с зажатым Ctrl (выбран нативный вариант из
предложенных).

## Что изменилось

- Новый модуль `folder_dialog.py`: системный диалог Windows
  `IFileOpenDialog` с флагами `PICKFOLDERS | ALLOWMULTISELECT` — тот самый
  Проводник, но папок возвращается столько, сколько отмечено (Ctrl/Shift).
  Реализация на чистом ctypes по COM-интерфейсам, без новых зависимостей;
  отмена — пустой список, COM-ресурсы освобождаются всегда.
- Кнопка «➕ Папку…» переименована в «➕ Папки…» и ведёт себя так:
  сначала нативный диалог (владелец — окно приложения), при любом его сбое —
  откат на прежний `askdirectory` в одну папку.
- Диалог открывается в родительской папке прошлого выбора (запоминается на
  сессию), а не внутри уже добавленной папки — вылезать наверх больше не надо.
- Подсказка статуса страницы «Данные» обновлена: «выбором (можно сразу
  несколько)».

## Проверка

- `tests/test_folder_dialog.py`: вне Windows диалог честно недоступен
  (FolderDialogError → откат).
- GUI-тесты: нативный диалог вернул две папки → обе в списке одним нажатием,
  начальная папка следующего диалога — родительская; сбой нативного диалога →
  откат на askdirectory и одна папка в списке.
- Полный pytest: **2138 passed, 14 skipped, 2 xfailed**.

Живой COM-диалог из песочницы не проверить — нужна проверка на Windows:
кнопка «Папки…» должна показать обычный Проводник, где Ctrl/Shift отмечают
несколько папок, и все они появляются в списке очереди. При любом сбое диалог
сам откатится на прежний одиночный — это тоже стоит заметить в журнале
поведения (тихий откат, без ошибки).
