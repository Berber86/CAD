# Примечания к версии 5.27 (2026-11-25 07:43)

## Что изменилось

1. **ACRIS-читалка: ожидание PDF 45 с вместо 300 (как Клерк в 5.26).** Если за 45 с после клика «PDF Document Download» не погаснет окно печати Internet Explorer, программа раньше 5 минут ждала капчу веткой «печати многостраничного документа» и дальше смотрела на экран. Итог падения и время падения — одинаковые, только раньше. Истина исхода по-старому проверяется скачанными файлами; теряется только тень шанса, что человек успел бы донести капчу за 5 минут.

2. **Аварийный снимок читалки `ACRIS_FAIL_*.png`** (как `CLERK_FAIL_*`/`PORTAL_FAIL_*`). При тайм-ауте в папку назначения падает снимок окна читалки, его путь дописывается в текст ручного шага. По нему видно, какая именно капча/страница задержала PDF.

3. **Галочка «Ждать долгую капчу (ожидание PDF 300 с вместо 45 с)»** — страница «Данные», под счётчиками. Когда поставлена: обоим источникам возвращается длинное ожидание — Клерку `watch_timeout=300`, ACRIS `download_wait_sec=300`. Когда снята (по умолчанию) — по 45 с в обеих системах. Действует на очередь «Данные» и на автопоток Шага 0; быстрый режим Шага 0 не тронут (там PDF и так не качаются). Значение из UI в `collect_deeds(pdf_wait_sec=...)` идёт параметром через `_step0_worker`; автопоток с длинным ожиданием пишет об этом строку в журнал.

## Что не менялось
- 300 с остались в программе двумя путями: галочка и прямая константа `PDF_WAIT_LONG_SEC`/`WATCH_LONG_SEC` — не хардкод по веткам.
- Капча капой по-прежнему решается руками (или общей гонкой моделей Шага 0.2); подсказка через HID никак не трогалась.
