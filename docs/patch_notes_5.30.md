# Примечания к версии 5.30 (2026-11-25 08:24)

## Что изменилось

**Копия PDF только из релевантных страниц — для ручной проверки описания.**

В автопотоке поиск определяет страницы с описанием (property line) и результат хранится в наших кэш-файлах, но пользователю для проверки приходилось листать весь исходный документ (хоть 34 страницы). Теперь, как только поиск вынес финальный вердикт, рядом с исходником появляется копия только релевантных страниц:

- Имя: `<исходное имя>_p<страницы через запятую>.pdf`, например `LOT 30 NEW_p2,4.pdf`.
- Лежит в той же папке, что и исходный PDF (в автопотоке — папка `data` задания).
- В журнал пишется строка: «Для проверки: копия только релевантных страниц — <имя>».
- Копия делается в конвейере разбора (`multiple_description_pipeline.parse_pdf`) — то есть и в автопотоке Шага 0, и в очереди «Данные», и при восстановлении результата из кэша (поиск при этом всё равно проходит по кэшированным ответам и вердикт финален).

Важное про момент создания: страницы оцениваются партиями по 8, и отдельная партия ничего не решает. Копия пишется только после того, как `search_pdf` проверил **все** партии и собрал окончательный `candidate_pages` — раньше этого момента файла не появляется и по неполному списку он не строится.

Если релевантных страниц нет — копии нет. Если копию сделать не удалось (файл изменился, страница вне документа и т.п.) — разбор не страдает: в журнал пишется «копию релевантных страниц сделать не удалось», работа продолжается.
