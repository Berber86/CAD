# Шаг 4: правила оффсетов и их оформления

Свод правил, по которым программа ставит оффсеты на чертёж межевания и оформляет подписи.
Здесь **всё, что применяется сейчас** (версия шага 4 — `STEP4_VERSION` = **4.26**), и всё, что
сознательно выключено, с причиной. Документ ведётся вместе с кодом: правило без строки здесь
считается не принятым.

Связанные документы:

| документ | что в нём |
|---|---|
| `docs/step4_hypotheses.md` | журнал замеров по версиям: какая гипотеза чем проверена и что отклонено |
| `docs/step4_rules_from_examples.md` | разбор пар «до/после» — что Николай дописал и как |
| `docs/step4_offsets_plan.md` | план шага и порядок работ |
| `docs/customer_rules.md` | ответы заказчика (Коля) по правилам и стилю |
| `docs/step4_ai_rules_reference.md` | сводка правил для ИИ-агента |

Источник каждого правила — **замер на реальных парах** «до/после» (`docs/primer1i.zip` — Alvine,
`docs/primer2i.zip` — Brooklyn, `docs/primer3i.zip` — Geldner, `docs/primer4i.zip` — Mother Gaston,
`docs/primer5i.zip` — 18 Zoe Street). Правило, которое ухудшает хотя бы
один чертёж, не принимается; правило, которое не подтверждается дампами, остаётся за флагом
`False`.

Пятая пара (`docs/primer5i.zip`, версия 4.27) — первая, где граница участка начерчена в **новом**
слое заказчика `PL` (три отрезка: запад, юг, восток; фасад — красная линия `M-ROW-LINE`). Она же
первая пара, к которой приложен **сам PDF**, поэтому по ней есть картинка поверх листа заказчика:
`docs/step4_zoe_preview.png` (`python docs/make_zoe_preview.py`). Правила оффсетов на ней пока не
подбирались — она вошла в замер как есть, первым числом (забор 7 эталон / 8 подписей / 3 совпало,
дом 2 / 0 / 0); метрика H17 по-прежнему считается по четырём прежним парам.

## 1. Термины

| термин | значение |
|---|---|
| оффсет | расстояние от объекта (дом, забор, стена) до стороны участка, подписанное на чертеже: `FE.0.4'N`, `3.2'S` |
| подпись целиком | одна запись оффсета: `FE.0.1'S` или столбик `FE.0.1'S` / `FE.0.5'W` |
| часть подписи | пара «значение + буква»: `0.1'S`, `0.5'W` |
| буква | сторона, **где стоит объект** относительно стороны участка: `FE.0.4'N` — забор севернее линии |
| эталон | подпись Николая в файле «после» (слой `D-TOPO-TEXT`, текст с цифрой) |
| вершина | точка контура объекта; подпись привязывается к вершине, а не к стороне |
| сторона участка | отрезок контура участка либо линия `M-ROW-LINE` (фронтовая граница) |

## 2. Критерии приёмки

**H17 (заказчик):** лишних подписей — не больше 50% от числа подписей Николая того же вида.
То есть при 20 эталонных подписях забора программа может поставить максимум 30, из них минимум
20 − 10 = 10 должны совпасть.

**Совпадение подписи** (`tests/test_field_dump.py::score`): подпись считается совпавшей, если

1. тот же вид объекта (`FE.` → забор, `WALL` → стена, иначе дом);
2. есть хотя бы одна общая часть: то же значение (±0.11 ft после округления) и та же буква
   (порядок строк не важен, `BLDG` не учитывается);
3. подпись стоит в 6 ft от эталонной (по якорю/тексту);
4. каждая эталонная подпись засчитывается **один раз**.

**Не входят в подсчёт:** `\A2;` без буквы (размеры дома) и `GEN.` — это не оффсеты; подписи
без числа (`FE.O/L`, `BLDG` / `O/L`) тоже не оффсет: у Николая они вне счёта, и программа их
в счёт не берёт.

Счёт ведётся по **подписи целиком**, а не по частям: у соседних веток часть считалась отдельно,
и метрика была мягче.

## 3. Конвейер

```
область (выделение в AutoCAD)
  └─ объекты в области: дом, сарай, забор, стена            §4
       └─ вершины с точкой съёмки, у которых DESC2 называет объект   §5
            └─ замер по нормали своего края (R11), второй край (R12),
               концы прогона, пересечения, наклонные      §6
                 └─ отбор вершин и дедуп подписей         §7
                      └─ текст подписи                    §8
                           └─ высота                      §9
                                └─ раскладка (текст / выноска)  §10
                                     └─ запись в чертёж (TEXT / MText, Leader)  §11
```

Точка входа — `offsets.plan_offsets(...)`, она возвращает `OffsetPlan` (items / skipped /
warnings / counts). Запись — `acad_builder.build_offsets()` → `draw_offset_labels()`.

```python
plan_offsets(
    property_pts,            # контур участка (замкнутый)
    features,                # [Feature(kind, handle, points, closed=None)]
    front=(),                # линии M-ROW-LINE
    area=None,               # область выделения; None — весь участок
    scale=BASE_SCALE,        # 1"=16'
    north_deg=90.0,          # из стрелки севера, ближайшей к участку
    texts=(),                # уже стоящие тексты: (текст, точка, высота)
    text_width=None,         # точная ширина строки; None — default_text_width
    survey_pts=(),           # точки съёмки (R13)
    survey_notes=(),         # (точка, DESC2) для R13b
)
```

## 4. Область, границы, объекты

| правило | значение | откуда |
|---|---|---|
| базовый масштаб | `BASE_SCALE` = 16 (1"=16'); высоты и допуски даны для него и пересчитываются пропорционально | настройки заказчика |
| слой подписей | `OFFSET_LAYER` = `D-TOPO-TEXT` | все подписи Николая лежат на нём |
| фронтовая граница | `FRONT_BOUNDARY_LAYER` = `M-ROW-LINE` — актуальная граница улицы и участка, считается стороной участка | ответ заказчика 4.1 |
| линия расширения | `WIDENING_LINE_LAYER` = `M-TAX-LINE` — **не** граница для оффсетов, в `plan_offsets` не передаётся | ответ заказчика 4.1 |
| допуск области | `AREA_EDGE_TOL_FT` = 6.0: объект считается попавшим в область, если он ближе этого к её границе | при выделении самой полилинии участка забор в 0.3 ft снаружи выпадал: Geldner 5 подписей вместо 14 |
| объект за границей | `OUTSIDE_MAX_FT` = 5.0: подписываем, если он не дальше этого от границы участка | Alvine `3.2'S` у строения за южной линией; `FE.0.2'S` в 0.24 ft снаружи |
| подпись снаружи участка | `LABEL_MUST_BE_INSIDE` = False: текст может стоять вне участка (в яру, у ворот) | у Николая 4 из 8 подписей вне линии участка |
| виды объектов | `OFFSET_KINDS` = (`house`, `fence`, `wall`); дом и сарай — текст без выноски, забор и стена — выноска | разбор дампов |
| стены | `WALL_OFFSETS` = False: стены не подписываются оффсетом, пока правило не подтверждено | отсутствие подписи у заказчика — не запрет, но и не правило |
| север | `north_deg` — направление на север из блока `NA`, **ближайшего к участку**; на листе до 12 блоков с разными поворотами | первая найденная стрелка давала север от порядка обхода |
| замкнутость контура | `Feature.closed`: если контур не замкнут, замыкающий отрезок объектом не считается | П-образный «дом» иначе получал стену через пролёт |

| правило | значение | откуда |
|---|---|---|
| R13: только снятые вершины | `LABEL_ONLY_SURVEYED_VERTICES` = True, `SURVEY_POINT_SNAP_FT` = 0.6 — метка ставится у вершины, рядом с которой есть точка съёмки | без этого на Geldner 27 подписей при 11 у Николая |

## 6. Как измеряется расстояние

### 6.1 R11 — по нормали СВОЕГО края

`EDGE_NORMAL_OFFSETS` = True. Оффсет меряется по нормали к краю объекта, а не до ближайшей точки
границы; замер идёт до той стороны участка, нормаль которой параллельна нормали края.

| параметр | значение | смысл |
|---|---|---|
| `EDGE_PARALLEL_TOL_DEG` | 3.0 | расхождение нормалей, при котором сторона считается «своей» |
| `EDGE_MAX_FT` | 3.0 | дальше этого «своя» сторона не ищется: у Николая замеры 0.1–3.0 ft |
| `LINE_CLEARANCE_FT` | 0.0 | текст оффсета держит просвет 0.4–0.7 высоты до любой линии | у Николая текст стоит от ближайшей линии на 1.60 (забор) и 0.71 (дом), у нас медиана 0.27 и 10% подписей ближе 0.1 — но включение стоит двух подписей на пяти парах (63 → 61, совпадений 35 → 33, предупреждений 1 → 5). Нужно решение: качество листа против числа подписей |
| `EDGE_FALLBACK_FT` | 0.0 | запасной радиус «до ближайшей стороны», если своей нет (0 — выключено) |
| `LINE_EXTENSION_FT` | 5.0 | основание перпендикуляра может лежать на продолжении стороны за её концом |
| `PARALLEL_EXTENSION_FT` / `PARALLEL_MAX_FT` / `PARALLEL_TOL_DEG` | 5.0 / 6.0 / 3.0 | те же пределы для расширенного поиска параллельной стороны |

Пример: забор вдоль западной границы с дальним концом, отогнутым на 0.04 ft, у Николая подписан
`0.4'W` (нормаль края), а не `0.3'N` (ближайшая точка границы). На Geldner это дало 4 попадания
вместо 1.

`4.9'N` (дом на Geldner) правилом не берётся сознательно: это замер до южной линии, а сторона с
параллельной нормалью дальше `EDGE_MAX_FT`.

### 6.2 R12 — второй край той же вершины

`SECOND_EDGE_FT` = **3.0** — если к вершине сходятся два края и второй замер не дальше этого, он
идёт **второй строкой той же подписи**. `SECOND_SIDE_FT` = 2.0 — то же для второй стороны участка
(у забора/стены).

Порог поднят 2.0 → 3.0 в 4.25 по дампам: у Николая на Brooklyn угол дома подписан `2.1'N` и
`3.0'W` — второй замер (до западной стороны) ровно 3.0 ft. При пороге 2.0 вторая строка
пропадала, подпись не совпадала с эталоном; дальше 3 ft вторых строк в четырёх парах нет.
Абляция: `second_edge_ft` 2.0 / 2.5 — без изменений, 3.0 / 3.5 — дом Brooklyn 2 → 3 совпадения
и лишних 4 → 3, остальные чертежи без изменений.

Примеры: `W.FE.` / `0.1'E` / `1.2'S` и `C.L.F.` / `0.6'S` / `1.1'E` (Geldner): 0.12 по
вертикальному краю (E) и 1.23 по горизонтальному (S) — разные края одной вершины.

### 6.3 Буква

`compass_letter(dx, dy, north_deg)`: вектор идёт **от границы к объекту**, берётся главная ось —
`N`, `S`, `E` или `W`. Проверено: Alvine 8 из 8, Brooklyn 5 из 5.

### 6.4 Пересечение забора с продолжением стороны

`CROSSING_LABELS` = True. Забор, обходящий угол участка снаружи, получает подпись в точке, где он
пересекает продолжение стороны (у такой точки нет съёмки, и правила R13/R13b к ней не относятся;
`OffsetItem.crossing` = True). Ставится только когда **оба** конца отрезка вне участка — иначе это
выход забора за границу, и он подписывается по своим вершинам.

Geldner: `FE.0.7'E`, `FE.1.4'E` на юго-востоке, где заборы идут в 0.7 и 1.4 ft восточнее границы.

### 6.5 Конец длинного прогона

| параметр | значение | смысл |
|---|---|---|
| `FENCE_END_MAX_FT` | 6.0 | конец прогона подписывается и в 5–6 ft от стороны |
| `FENCE_END_MIN_LENGTH_FT` | 20.0 | только для прогонов не короче этого |

Geldner `FE.5.2'S` — забор в 5.17 ft южнее южной границы; на Brooklyn такой же вылет 5.3 ft у
6-футового выступа Николай **не** подписал.

### 6.6 Наклонные стороны

| параметр | значение | смысл |
|---|---|---|
| `DIAGONAL_SHEET_AXES` | True | буква наклонной стороны — по осям листа, а не по ближайшей оси |
| `DIAGONAL_TOL_DEG` | 10.0 | допуск «сторона наклонная» |

Alvine: Николай пишет `1.3'W`, `1.4'E` у наклонной восточной стороны, хотя при севере 67.6°
«ближайшая ось» дала бы N/S. У ортогональных сторон правило ничего не меняет.

**Двойное направление диагонали** (например `NE`) заказчик упомянул для R3, но формат не уточнил —
в код не внесено.

### 6.7 Объект на самой линии (правило `O/L`)

| параметр | значение |
|---|---|
| `MIN_OFFSET_FT` | 0.05 — ближе объект считается стоящим на линии, смещения нет |
| `ONLINE_LABELS` | **True** (с 4.24) — объект на линии подписывается `O/L`, а не числом |
| `ONLINE_TOL_FT` | 0.75 — допуск «вершина на контуре участка» |
| `ONLINE_FENCE_TEXT` / `ONLINE_TEXT` | `FE.O/L` и `O/L` |
| `ON_LINE_USES_EDGE` | True — у вершины на линии метка идёт по второму краю (первый даёт ноль) |

У Николая это `FE.O/L` (Geldner — забор на контуре), `BR.WALL` / `O/L` (Brooklyn — стена) и
`BLDG` / `O/L` дважды (378 Mother Gaston — дом в углу на фронтовой линии, высота 1.1).

Правило по замерам:

1. «На линии» — **ближайший** замер вершины меньше `MIN_OFFSET_FT`. Маленький оффсет (0.1–0.3)
   — это обычная числовая подпись, у Николая таких много.
2. У **забора** — на любом контуре участка; у **дома и стены** — только на **фронтовой линии**
   (`M-ROW-LINE`): на боковых линиях участка Gaston у того же дома стоит `BLDG` / `0.2'S`.
3. Текст: `FE.O/L`; `BLDG` / `O/L`; `WALL` / `O/L`. Оформление — как у обычной подписи
   (выноска, высота по виду объекта, привязка 4/6).
4. Одна подпись на объект; повтор ближе `DUPLICATE_RADIUS_FT` (10 ft) не ставится — в Gaston
   у Николая в одном углу стоят две `BLDG` / `O/L`, программа ставит одну.
5. Числовая подпись у такой вершины **не** ставится: смещения нет.

Замер по четырём парам: Geldner 1 (у Николая 1), Brooklyn 1 (у Николая `FE.O/L`), Gaston 1 —
в том же углу, где его две `BLDG` / `O/L`, Alvine 0 (у Николая 0). На H17 правило не влияет:
подписи без числа в подсчёт не входят (см. §2).

## 7. Отбор вершин и дедупликация

| правило | параметр | откуда |
|---|---|---|
| R13c: кэп «один угол на сторону» не склеивает разнесённые углы | `MAX_CORNERS_PER_SIDE` = 1, `SIDE_CAP_SPACING_FT` = 30.0 | Brooklyn: забор 100 ft вдоль западной стороны подписан у двух концов |
| R13d «перекос»: второй угол той же стороны подписывается, если его замер отличается от уже подписанного | `SKEW_PAIR_FT` = 0.2 | Gaston: забор `fence/4` — `1.0'S` у северного конца и `2.2'S` у южного; Geldner `FE.0.6'E` рядом с `0.7'E`. При равных замерах второй угол не дублируется (при `MAX_CORNERS_PER_SIDE` = 2 без этой разницы на Geldner лишняя `FE.0.3'W` при уже стоящей `FE.0.4'W`) |
| у дома свой предел | `MAX_CORNERS_PER_SIDE_HOUSE` = 2 | Brooklyn: `3.5'S`, `4.0'N`, `3.0'W` — по метке на юг, север и запад |
| R14: один замер у объекта — не больше двух раз | `MAX_SAME_VALUE_PER_FEATURE` = 2 | Geldner: два `0.7'E`; третий такой угол не подписан |
| R14: две вершины ближе 0.35 ft — один угол | `NODE_DUP_FT` = 0.35, `NODE_DUP_ANY_VALUE` = True | Brooklyn: стык двух заборов в углу даёт две вершины в 0.2 ft — у Николая одна подпись |
| тот же текст рядом | `DUPLICATE_RADIUS_FT` = 10.0 | иначе два одинаковых `0.3'W` у соседних объектов |
| уже стоящая подпись | `EXISTING_LABEL_RADIUS_FT` = 6.0 | R16: дубль, который есть в «до»-файле, не повторяем |
| часть подписи не повторяется рядом с полной | `POST_PART_DEDUPE` = True, `PART_DUPLICATE_FT` = 2.0 | H32: рядом с `0.1'E` / `1.2'S` отдельная `1.2'S` — дубль; Geldner −3 подписи без потери совпадений |
| порядок дедупа | **после** раскладки | дедуп до раскладки менял порядок и давал 31 подпись вместо 27 |

Отклонено по замерам: «одна подпись на вершину» (ветка 3c), отсев оффсетов < 0.5 ft,
`SAME_CORNER_FT` (у Николая две подписи в 1.5 ft на одном углу — Geldner `FE.1.7'S` и
`C.L.F. 0.2'S`), `TYPE_PREFIX_FT` (повторять тип забора в подписи).

## 8. Текст подписи

### 8.1 Форма

`offset_text(kind, value, direction, leader=)`:

| вид | вид подписи | пример |
|---|---|---|
| забор | `FE.` + значение | `FE.0.4'N` |
| стена | `WALL ` + значение | `WALL 0.5'E` |
| дом, текст у стены | только значение | `3.2'S` |
| дом, выноска | `BLDG` отдельной строкой + значение | `BLDG` / `2.5'S` |

Значение — до **0.1 ft, половина вверх** (`round_offset_ft`: 0.05 → 0.1, 0.04 → 0.0;
как у заказчика: 0.4, 3.2, 14.6).

### 8.2 Столбик (несколько частей)

| правило | как |
|---|---|
| `FE.` повторяется в каждой строке | `FE.0.4'N` / `FE.1.3'W` |
| имя типа — только в первой строке | `C.L.F.` / `0.6'S` / `1.1'E`; `BLDG` / `2.5'S` |
| первой идёт сторона N/S, второй E/W | 4 случая из 5 у Николая |
| каждая строка — отдельная часть, порядок остальных — по замеру | — |

Правило 4.22 «столбик без повтора префикса» **опровергнуто** дампами в 4.23: повторяется не имя
типа, а `FE.`.

### 8.3 Чего в подписях нет

| не пишем | почему |
|---|---|
| `\A2;` (подчёркнутый размер), `\pxqc;` (абзац) | это подписи размеров дома, `DIMENSION_LABELS` = False |
| `GEN.0.5'W` | один случай на три пары, второй пары для проверки нет |
| `COL.\P5.4'W`, `CLEAR` | по одному разу на три пары, условие появления не восстановить |
| `CONC. WALL ALONG LINE` | стена идёт ровно по линии участка; у нас эту роль играет `WALL` / `O-L` (§6.7), форма «ALONG LINE» — кандидат 4.26 |
| `3'-6" R.O.W. EASEMENT` | стоит уже в «до» (Brooklyn) — чужая надпись, свои мы не правим |
| `60' ADOPTED`, `50' RECORD` | ярлык ширины улицы по `M-TAX-DIM`, а не оффсет объекта |
| `AWNING 4.5'E` | оффсет от навеса: такого вида объекта у нас нет (2 случая на четыре пары) |
| дописывание в существующую подпись (`C.L.F.` → `C.L.F.\P0.2'S`, `W.FE.` → `W.FE. 0.2'E`, `CONC. STEP` → `C.STEP 5.9'S`, `AWNING` → `AWNING 4.5'E`) | 4 случая в одном файле (Geldner) + 1 в Gaston; требует правки существующих объектов «до» по ручке, поэтому вынесено в кандидаты 4.26 (см. §13.4) |
| размеры стен (R6–R8) | `DIMENSION_LABELS` = False: какие стены размеряет заказчик, не подтверждено (Geldner: 2 из 4) |

### 8.4 Поворот текста (R10)

`TEXT_FOLLOWS_BOUNDARY` = **True** — подпись **без выноски** пишется вдоль своей линии: 0° у
горизонтальной границы, 90° у вертикальной. Подпись **с выноской** всегда горизонтальна (у Николая
текст выноски не повёрнут ни в одном дампе), поэтому правило применяется только к `style == "text"`.

Замер по дампам (все — подписи с числом на слое `D-TOPO-TEXT`):

| чертёж | оси участка | поворот подписей | сколько по осям |
|---|---|---|---|
| 12 Ilion Place (final) | 0.4° / 90.4° | 0.4° и 90.4° | 18 из 19 (одна — 70.8°) |
| 225 Aspinwall (final) | 14.6° / 284.6° | 14.6° и 284.6° | все (0° «по сетке листа» — ни одной) |
| 6910 15th Ave (final) | 356.5° | 356.5° | все |
| Geldner / Brooklyn / Alvine | оси листа | 0° и 90° | все |
| 378 Mother Gaston | 0.03° | 0° и 90° | все |

На четырёх полевых парах у наших подписей без выносок поворот совпал с Николаем у **6 из 6**
(Gaston `2.4'S` — 88.6°, Geldner `0.4'W` — 90°); с выключенным правилом — у 2 из 5.

До 4.26 флаг стоял выключенным: 284.6° у Aspinwall было прочитано как «не вдоль стороны», хотя
это вторая ось участка, повёрнутого на 14.6°; то же с Ilion (0.4° — ось участка, а не «сетка листа»).
Ошибка нашлась при сверке с параллельной веткой `arena/3c6f7f95-cad` (её 4.31).

Габарит повёрнутой подписи считается по описанному прямоугольнику (`_text_block(..., rotation_deg)`):
у вертикальной подписи ширина и высота меняются местами. Без этого подпись проверялась как
горизонтальная — на 192 Geldner повёрнутый текст накрыл бы существующий `C.L.F.`. С поворотом:
наложений на тексты — 0, пересечений с линиями — 14 на четырёх парах.

## 10. Раскладка: где подпись стоит

### 10.1 Габарит блока

| параметр | значение | смысл |
|---|---|---|
| `TEXT_CHAR_WIDTH` | 0.70 | ширина знака в долях высоты (медиана `bbox` подписей Николая — 0.705; оффсеты 0.70–0.75) |
| `TEXT_LINE_SPACING` | 1.67 | шаг строк MText: двухстрочный блок занимает 2.67 высоты, а не 2 |
| `TEXT_GAP_FACTOR` | 0.3 | зазор текста до линии и до конца выноски, в высотах |

Точная ширина приходит из `acad_builder.feature_text_width()` (таблица шагов шрифта romans);
`default_text_width()` — оценка `0.70·h·len`, когда точной нет.

### 10.2 Порядок попыток

**Дом:** текст внутри контура у стены (`HOUSE_TEXT_INSIDE` = True, `_place_house_text`) →
текст сбоку от линии измерения (`_place_beside_line`) → выноска с `BLDG`.

**Забор и стена:** выноска (`FENCE_TEXT_WITHOUT_LEADER` = False) — у Николая стрелка есть у всех
заборных подписей. Текст без выноски включается флагом и даёт «частокол» на плотных чертежах.

### 10.3 Выноска

| параметр | значение | смысл |
|---|---|---|
| `LEADER_DISTANCES_FT` | (0, 0.5, 1.5, 3.0) | добавка к «половина габарита + зазор», в порядке попыток |
| `LEADER_ANGLES_DEG` | (90, −90, 60, −60, 120, −120, 30, −30, 150, −150, 0, 180) | направления относительно линии измерения; перпендикуляр первым |
| `LEADER_MIN_HEIGHTS` | 2.0 | короче двух высот AutoCAD не нарисует стрелку |

Длина выноски считается **от габарита блока**: `d = |ux|·w/2 + |uy|·h_блока/2 + зазор + добавка`.
У Николая 2.67–4.35 ft (медиана 3.1) при высоте 0.9; прежняя лестница (4, 5.5, 7) давала 5–8 ft.

**Замер по пяти парам (4.28).** Длина выноски у Николая — от острия стрелки до ближайшего края
блока: забор **33 подписи, медиана 2.61**, p10 2.06, p90 3.23, max 3.91; дом с выноской (6 из 22) —
медиана 2.59. У нас при `(0.0, 0.5, 1.5, 3.0)` — медиана **2.01** (p10 1.88, p90 3.91, max 4.13),
то есть подписи жмутся к объекту и разброс больше. Кандидат — начать с длинной выноски:
`(2.0, 2.6, 1.5, 1.0, 0.5, 0.0, 3.2)` даёт медиану **2.96** при тех же 63 подписях, 35 совпадениях
и одном предупреждении. Порядок «сначала длинная, короткие — в конце» важен: если начать с 1.2–1.5 и
не оставить коротких вариантов, две подписи перестают влезать (63 → 61, совпадений 35 → 33).
Замер: `docs/step4_spatial_measure.py`.

### 10.4 Зазоры и повторный заход

| параметр | значение | смысл |
|---|---|---|
| `LABEL_CLEARANCE` | 0.35 | зазор между подписями в высотах: сравниваемые прямоугольники расширяются с обеих сторон |
| `LABEL_RELAXED_RETRY` | True | если со зазором места нет — второй заход **без** зазора |

Минимальный зазор между подписями Николая — 0.72–0.84 ft (0.8 высоты); строгая проверка считала
такие места занятыми, и Geldner `FE.0.4'N` не находил места, хотя стоит вплотную к `V.FE.`.

### 10.5 Что считается занятым

1. Все тексты чертежа на слоях подписей (`texts`), их прямоугольники с зазором.
2. Уже разложенные подписи этого прохода (`placed`).
3. Линии чертежа (`lines`) — подпись не пересекает отрезок, кроме границ далеко за пределами
   области (`_area_bounds`, запас 15 ft × масштаб). Просвет до линий — `LINE_CLEARANCE_FT`
   (0 — только пересечение; §12).
4. Если дедуп частей снял подпись — её прямоугольник **убирается** из занятых. Иначе «фантом»
   глушил следующие объекты: Geldner `FE.0.4'N` и `FE.1.1'E` не находили места при свободном поле.

## 11. Запись в чертёж

| что | как |
|---|---|
| однострочная подпись | `AcDbText` (`AddText`) |
| многострочная подпись | один `AcDbMText`, строки через `\P`: `FE.0.6'S\PFE.1.1'E` |
| привязка MText | 5 (middle-center) для текста без выноски; **4** (влево-середина) если текст справа от стрелки и **6** (вправо-середина) если слева |
| точка вставки MText с выноской | ближний к стрелке край блока; конец выноски — в этой же точке |
| слой | `D-TOPO-TEXT` (цвет из настроек; если слоя нет — слой 0 и предупреждение) |
| стиль текста | стиль подписей чертежа (`_label_text_style`), шрифт romans |
| выноска | объект `Leader`: тип 3 (сплайн со стрелкой), 2 точки, `Leader.annotation` = MText подписи |
| размер стрелки | из текущего размерного стиля (у заказчика `CURB-DIM 1-16`: 1.2 ft); свой — только если тот несоразмерен тексту |
| отмена | одна группа Undo на все подписи |
| ошибки | одна подпись не валит остальные: причина уходит в `result.failed` / предупреждения |

Обоснование привязки: 13 замеров у Николая — знак `dx` (текст справа/слева от стрелки) совпал с
привязкой 4/6 во всех случаях. Текст растёт **от** выноски и не накрывает стрелку.

Поворот текста — §8.4: подпись без выноски идёт вдоль своей линии (`TEXT_FOLLOWS_BOUNDARY` = True).

`max_corners_per_side_house` 1/3, `side_cap_spacing_ft` 15/20/40, `survey_point_snap_ft` 0.3/1.0,
`survey_desc_rule` False, `edge_parallel_tol_deg` 6, `diagonal_tol_deg` 20,
`max_same_value_per_feature` 1/3, `node_dup_ft` 0.2/0.5/0.75, `outside_max_ft` 6,
`fence_end_max_ft` 4/8/10, `fence_end_min_length_ft` 10/30, `duplicate_radius_ft` 6/8,
`existing_label_radius_ft` 3/4, `online_tol_ft` 1.0/1.5, `online_fence_text` `O/L`,
`edge_fallback_ft` 1/2/3, `line_extension_ft` 10/15, `min_offset_ft` 0.15/0.25,
`part_duplicate_ft` 1/3, `on_line_uses_edge` False, `parallel_max_ft` 99. **Приняты два**
(`SKEW_PAIR_FT`, `SECOND_EDGE_FT` = 3.0, §6.2 и §7); остальные либо не меняют метрику (мёртвые
или безопасные: `online_tol_ft`, `duplicate_radius_ft`, `part_duplicate_ft`,
`existing_label_radius_ft`, `edge_fallback_ft`, `fence_end_min_length_ft`), либо хуже
(`line_extension_ft` 10+ и `fence_end_max_ft` 8+ дают по +2 лишних на Brooklyn и Gaston,
`min_offset_ft` 0.15 режет настоящие 0.1, `node_dup_ft` 0.5 склеивает разные углы,
`side_cap_spacing_ft` 40 — 3 угла одной стены).

**Дописывание оффсета в существующую подпись** (ориентир ИИ, категория 1 п. 2). Николай не
всегда ставит новую выноску — иногда он **правит текст объекта, который уже есть в «до»**:

| было (тип) | стало | чертёж |
|---|---|---|
| `C.L.F.` (MText) | `C.L.F.\P0.2'S` | Geldner |
| `W.FE.` (MText) | `W.FE. 0.2'E` | Geldner |
| `CONC. STEP` (Text) | `C.STEP 5.9'S` | Geldner |
| `AWNING` (Text) | `AWNING 4.5'E` | Gaston |

Что из этого следует: оффсет дописывается **без префикса `FE.`** (имя типа уже в тексте),
разделитель — **пробел** в 3 случаях из 4 (`\P` — 1 раз, `C.L.F.`), имя объекта при дописывании
**сокращается** (`CONC. STEP` → `C.STEP`). Случаев на два чертежа — 5; правило меняет не
геометрию, а то, какой объект правится, поэтому нужен доступ к ручке существующего текста на
этапе записи (`acad_builder`), а не к плану. Отложено до 4.26.

**`ALONG LINE` у стены по линии.** Geldner: `CONC. WALL` → `CONC. WALL ALONG LINE` — стена,
идущая ровно по линии участка, подписана словами вместо числа (одна пара). У нас эту роль играет
`WALL` / `O-L` (§6.7, `ONLINE_LABELS` = True) — форма подтверждена только одним случаем, поэтому
не вводится. Там же в ориентире: подпись только у углов с точкой съёмки (уже R13) и «буферная
зона 2.0–3.0 ft» (отдельного параметра в дампах не видно: `EDGE_MAX_FT` = 3.0 и есть этот
порог).

### 13.5 Пятая пара: 18 Zoe Street, Staten Island (4.27)

Первая пара, к которой приложен **сам PDF заказчика** (`docs/primer5i.zip`: PDF + два дампа,
«2» — до оффсетов, «3» — с подписями Николая). Поэтому по ней есть картинка поверх его листа:
`docs/step4_zoe_preview.png` (собирается `python docs/make_zoe_preview.py`, нужны `pymupdf` и
`Pillow`; лист 1"=16', положение чертежа на растре находится корреляцией контуров дампа с листом).

**Граница участка.** Впервые — новый слой `PL`: три отрезка (запад, юг, восток), фасад
замыкается красной линией `M-ROW-LINE`. Контур 4469.9 sq ft; на листе «TOTAL AREA: 4,470.0 Sq. Feet».
Старый `ST-BLDG-LINE` на этом же чертеже — линии дома и 21 вставка, участком он не является,
поэтому в `property_line_layers` порядок такой, что `PL` перекрывает `ST-BLDG-LINE`.

**Первое число (правила под пару не подбирались):** забор 7 эталон / 8 наших / 3 совпало,
дом 2 / 0 / 0. Совпали `FE.0.3'N`, `FE.0.5'N` (оба у северо-западного угла) и двухчастная
`FE.0.4'E`/`FE.0.8'N` у юго-западного.

| что у Николая | что у нас | почему |
|---|---|---|
| `BLDG` / `6.8'S` | нет | дом стоит в 6.6–6.8 ft от восточной стороны, дальше `EDGE_MAX_FT` = 3.0; при этом его подпись меряет до **южной** стороны, а у нас ближайшая параллельная стена — восточная |
| `BLDG` / `2.0'N` (сарай) | нет | сарай соседа за восточной границей, контур не наш |
| `FE.0.3'S` / `FE.0.1'W` (юго-восточный угол) | `FE.1.2'E` | меряем до восточной стороны, он — до южной и западной: выбор стороны у наклонного угла |
| `FE.0.7'E` / `FE.0.3'N` (юго-западный угол) | `FE.0.4'S` / `FE.0.8'N` | второй угол той же вершины: у него ближняя сторона — южная, у нас — западная |
| `FE.5.4'W`, `FE.5.3'W` (забор у фасада) | `FE.0.5'N`, `FE.5.2'N`, `FE.0.6'W`, `FE.1.1'N`, `FE.0.2'N` | подписи есть, но у других вершин: у него забор фасада меряется к красной линии, у нас — к боковым |

**Проверено и отклонено:** `HOUSE_EDGE_MAX_FT` (отдельный предел для дома) — 3.5 даёт +1 совпадение
на Alvine и +1 лишнюю, 4.0 — дом 24 подписи / 12 совпало / 12 лишних (было 16 / 9 / 7), 7.0 — на Zoe
появляются 2 подписи дома, но **ни одного совпадения** (значение и буква не те), а лишних становится
24. Предел оставлен общим `EDGE_MAX_FT` = 3.0.
